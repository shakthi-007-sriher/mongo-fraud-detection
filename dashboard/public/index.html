    How to work this dashboard

    First time

    1. Open Live monitor. Click Start next to Detector, then Start next to Demo traffic. (Or run them in terminals with npm run detector and npm run generator.)
    2. Wait about a minute. The first minute is normal traffic, so the system can learn what is normal for each user. Then fraud is injected and the banner starts flashing.
    3. Click any red row, or the banner, to see why it was flagged.

    The new tabs

    Radar
    A live radar of all scored transactions, pushed from a MongoDB change stream. Distance from the centre is the risk score. Click a dot for the explanation.
    Attack lab
    Launch a botnet, card-testing or impossible-travel attack against the running system and watch the verdicts.
    Fraud rings
    Accounts that share a device, found with $graphLookup and drawn as a graph. Launch a botnet in the Attack lab, then press Find rings.
    Rule builder
    Write your own rule (amount, risk, z-score, velocity, country, device) and back-test it against recent history. It reports precision and recall next to the built-in model. It is a sandbox: it does not change what the detector flags.

    Country and device appear in the explanation as context. The built-in risk score itself uses only the amount and the velocity.

    The original tabs

    Live monitor
    A ticker of every scored transaction (red = flagged), charts, the alert list and the pipeline controls. Pause freezes the screen (data keeps flowing in MongoDB). Flagged only hides normal rows. Sound beeps on each new alert.
    Investigate
    Pick a user (type an id, or use the chips) to see their typical amount, spread, alert count, a chart of their amounts with the rolling average and an upper limit, and their latest transactions. Click a dot or row for the explanation.
    Try it yourself
    Play the fraudster. Enter a user and an amount and send it. Try an amount close to their typical value (normal), then Send a spike (10 times typical) and Send a burst (12 transactions in 3 seconds). Each verdict appears with its risk score and latency.
    Tune & what-if
    The chart shows precision (how many alerts were real fraud) and recall (how much fraud was caught) for every threshold, calculated by MongoDB from recent traffic. Drag the threshold slider to see the trade-off. Save applies the settings to the running detector.

    What the numbers mean

    Risk (0 to 100)
    How suspicious the transaction is. At or above the threshold (default 60) it is flagged.
    z-score
    How many "standard deviations" the amount is from this user's typical amount, measured on a log scale. Around 0 is normal; above about 4.6 alone is enough to flag.
    Velocity
    How many transactions this user made in the last 5 seconds. The 7th within 5 seconds alone is enough to flag.
    Warm-up
    A user needs 20 earlier transactions before their amounts are judged. Until then only velocity counts.
    Precision and recall
    Only available for events the generator or this page labelled as fraud (spike or burst). Precision = flagged events that were real fraud. Recall = real fraud that was flagged.

    Keyboard

    1 to 9 switch tabs, p pauses the live view, Esc closes the explanation panel.

    If something looks wrong

    • Banner says "No anomalies yet" for a long time: the detector or the traffic is not running, or the first minute has not passed.
    • "Try it" shows "no verdict": the detector is stopped.
    • Status shows "offline": the page cannot reach the dashboard server. Is npm run dashboard still running?
    • Start does nothing, log mentions mongosh: mongosh is not installed or not on PATH.
